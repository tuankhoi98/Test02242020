Where Claude Code runs

The same Claude Code agent can run in three places. The difference that matters most is which machine runs the agent loop: the program that reads files, runs commands and asks the model what to do next. In every setup the model itself runs on Anthropic's servers.

What happened when you sent your prompt

  1. claude.ai started a container from your environment's settings.
  2. The container cloned your repo and checked out claude/code-architecture-comparison-6lczvh.
  3. The agent loop ran in the container: ask the model, run a tool (write a file, run git), repeat.
  4. It committed and pushed this page to the branch on GitHub.
  5. When the session goes idle the container is deleted. Only what was pushed survives.

Claude Code in the terminal

You install the claude command on your own machine and run it inside a project folder. The agent loop is a local process. It edits your real files and runs commands in your shell, as you, after asking permission.

Claude Desktop app

A native Mac or Windows app. In its Code view it runs the same Claude Code engine locally on a folder you pick, like the terminal, but with a graphical interface. It can also start and monitor cloud sessions like this one, and its chat side can reach things on your machine through local extensions.

Things to know on the web

  • Anything not pushed to GitHub is gone once the container is reclaimed.
  • Claude only sees repositories you granted the Claude GitHub App. You add more in your GitHub settings.
  • If your project needs a tool or package installed, put it in the environment's setup script so every new session has it.
  • Blocked downloads or API calls usually mean the network policy doesn't allow that host. You can change the policy in the environment settings.
  • Claude creates a pull request only when you ask for one.
